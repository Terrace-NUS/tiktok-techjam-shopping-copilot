# 07：自然语言回复如何生成

## 一句话版本

回复层不再调用一次 DeepSeek，也不重新判断商品。它只把当前 `T_t`、最终推荐顺序，
以及排名阶段已经产生的商品理由和疑点组织成自然语言。

```text
最终 Top-10
  + 当前 T_t / 上一轮 T_t
  + DeepSeek 排名阶段的 reason / concerns
  + catalog 商品标题与类别
  -> 确定性回复编排器
  -> message + 实际 follow-up question
```

`ask_attribute` 对外继续固定为 `other`，因为自然语言环境真正读取的是 `message`。

## 为什么不再调用一次模型

排名阶段已经让 DeepSeek 阅读了完整 Session Context 和商品证据，并为每件候选商品
产生了匹配理由、证据缺口和冲突。再次调用模型会带来三个问题：

- 增加延迟和 token；
- 可能改变已经确定的推荐顺序；
- 可能重新编造商品事实。

因此回复层没有修改推荐结果的权力，只负责表达。

## T_t 如何影响回复

这里的三个区间只是展示用语，不会反过来改变 `T_t` 或检索算法。

| 展示状态 | 条件 | 回复行为 |
| --- | ---: | --- |
| broad | `T_t < 0.35` | 明确告诉用户保留了多个商品方向，避免近似重复 |
| narrowing | `0.35 <= T_t < 0.70` | 说明搜索正在收窄，但仍保留少量真正不同的选项 |
| focused | `T_t >= 0.70` | 强调最接近要求的商品及仍未确认的细节 |

如果相邻两轮的 `T_t` 变化绝对值达到 `0.12`：

- 上升：回复明确说新增信息让搜索收窄；
- 下降：回复明确说用户的变化重新打开了搜索空间；
- 小幅变化：不夸大变化，只按当前状态表达。

用户改变主意导致 `T_t` 大幅下降是正常行为，不会被强行平滑或描述成错误。

## 商品说明从哪里来

每条商品说明只能使用：

- catalog 中的商品标题和类别；
- DeepSeek 排名阶段已经验收的 `reason`；
- 同一判断中的第一条 `concern`；
- 如果质量排名不可用，则使用“当前搜索中最强的候选之一”这一排序事实。

回复层不会从标题猜测新属性，也不会改变 Top-10 顺序。

## 追问如何生成

如果 Top-3 中有至少两件商品都无法验证同一个当前偏好，回复会直接指出这个证据缺口。
硬偏好会询问是否应排除没有明确证据的商品；软偏好会询问是否需要把它升级为不可妥协条件。

没有共同证据缺口时：

- broad：询问用户想先收窄哪个商品方向；
- narrowing：询问下一步更重视哪种风格或取舍；
- focused：询问是否还有一个不可妥协的细节。

这个真实问题会同时：

1. 出现在 `message` 末尾；
2. 写进本轮 `TurnRecord.question`；
3. 作为下一轮 Query Understanding 的 `last_question`。

所以自然语言对话和 Session Context 中记录的交互现在是一致的。

## 失败边界

- 没有推荐结果：说明当前条件下没有可靠匹配，并询问哪条条件可以放宽；
- DeepSeek 质量排名降级：仍可根据 BGE/DPP 顺序生成回复，但不编造逐件匹配理由；
- toy simulator 分支：不使用这个回复编排器，继续保持独立策略。
