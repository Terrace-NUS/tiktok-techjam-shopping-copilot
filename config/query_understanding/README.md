# Query Understanding prompt suites

This directory keeps two deliberately separate evaluation cohorts:

- `natural-prompts-v0.json` is hand-authored conversational shopping language. Its
  critical assertions check meaning after local materialization, not exact model JSON.
- `simulator-prompts-v0.json` is generated by driving the organizer's public toy
  simulator. It is a compatibility cohort, not evidence of real-world language quality.
- `simulator-other-prompts-v1.json` captures all 80 buying and 80 browsing tasks
  for four visible turns while always returning `ask_attribute="other"`. This is
  the primary toy-simulator cohort for measuring whether `C_t` converges when the
  simulator discloses its remaining constraints. The older rotating-attribute
  suite remains useful only for broad QU protocol coverage.
- `intent-space-natural-prompts-v1.json` is a metric-focused paired suite: 24
  conversations / 48 turns, split into 16 expected-narrower, 3
  expected-broader, 2 expected-stable, and 3 goal-override trajectories. It
  evaluates intent-space behavior without pretending that every user turn must
  monotonically narrow the search.
- `intent-space-natural-prompts-v2.json` expands that metric cohort to 60
  conversations / 130 turns: 36 expected-narrower, 10 expected-broader, 7
  expected-stable, and 7 goal-override trajectories. Ten narrowing cases use
  three progressive turns, and the suite includes English, Simplified Chinese,
  code-switching, negation, partial constraint release, empty-intersection
  pressure, presentation-only turns, and cross-domain goal changes. It is
  deterministically generated by `build_intent_space_suite_v2.py` from v1 plus
  reviewed additions.

The natural suite is the semantic oracle: **40 conversations / 72 user turns**, with
12 conversations (20 turns) tagged for smoke runs. It covers colloquial wording, multilingual
utterances, corrections, retractions, exclusions, don't-care, goal changes, price and
brand constraints, references to shown products, behavioral directives, and ambiguous
language. Assertions intentionally leave room for model judgment around incidental
wording, confidence, and hard/soft strength unless the user makes strength explicit.

The simulator suite contains **32 conversations / 128 user turns**, balanced at eight
conversations per official scenario with one smoke conversation per scenario. It contains
only messages that the public evaluator actually passes to
`Agent.respond`, plus runner-only provenance. Target ASINs, catalog products, hidden intent
cards, undisclosed constraints, behavior plans, and reset profiles are forbidden from the
fixture and from Query Understanding requests.

Generate or verify the simulator fixture with:

```powershell
.venv\Scripts\python.exe scripts/query_understanding/generate_simulator_prompts.py
.venv\Scripts\python.exe scripts/query_understanding/generate_simulator_prompts.py --check
.venv\Scripts\python.exe scripts/query_understanding/generate_simulator_other_prompts.py
.venv\Scripts\python.exe scripts/query_understanding/generate_simulator_other_prompts.py --check
```

Validate both suites without network access with:

```powershell
.venv\Scripts\python.exe scripts/query_understanding/evaluate_prompts.py --validate-only
```

For the toy simulator, intent-space experiments intentionally use at most the
first three visible turns. Both the QU-to-Probe runner and the semantic-space
analyzer expose `--max-turn 3`; the original four-turn fixture remains unchanged
and auditable.

Live DeepSeek runs are opt-in. Credentials are read only from the explicitly selected
file or environment variable and are never included in reports:

```powershell
.venv\Scripts\python.exe scripts/query_understanding/evaluate_prompts.py `
  --tier smoke --api-key-file dpskapi `
  --output artifacts/query-understanding/deepseek-smoke-v0.json
```

`--tier smoke` runs only conversations tagged `smoke`; `--tier full` runs every
conversation. Generated reports belong under ignored `artifacts/` and record fixture,
prompt, tool-schema, model, and semantic-release identities so results remain auditable.
